# MPC Sample hardware test matrix

Тестовый набор создаётся скриптом:

```powershell
python scripts/make_hardware_test_kit.py `
  --template "D:\MPC-Sample\Projects\                0.xpj" `
  --output "D:\MPC-Sample\Projects\XPJ Hardware Test"
```

Перед тестом сделайте резервную копию проектов на устройстве.

## Проекты

### 1. `XPJ Test Notes`

17 коротких тональных семплов, по одному на ноту:

| MIDI note | Pad | Ожидание |
|---:|---:|---|
| 35 | 128 | низкий тон |
| 36 | 1 | следующий тон |
| 37 | 2 | ... |
| ... | ... | ... |
| 51 | 16 | самый высокий тон |

Sequence играет по одной ноте на beat в возрастающем порядке.

Проверить:

- каждая нота попадает на свой pad;
- тон меняется по возрастанию;
- нет «missing files»;
- семплы не обрезаются в самом начале.

### 2. `XPJ Test Loop`

Один loop-семпл на note 36, `loop = true`, sequence на 4 такта.

Проверить:

- звук не останавливается после первого прохода;
- нет щелчка/разрыва на точке склейки;
- loop держится все 4 такта.

### 3. `XPJ Test Long`

Один длинный one-shot (5 секунд) на note 36, нота в sequence короткая.

Проверить:

- семпл звучит целиком, а не обрезается по note-off;
- `sampleEnd`/`sliceInfo.End` не мешают воспроизведению.

### 4. `XPJ Test 128`

128 WAV-файлов.

- `00_note_35.wav` → note 35 → pad 128;
- `sample_001.wav` → note 36 → pad A1;
- `sample_002.wav` → note 37 → pad A2;
- ...
- `sample_016.wav` → note 51 → pad A16;
- `sample_017.wav` ... `sample_127.wav` → свободные pads.

Проверить:

- проект загружается без ошибок;
- все 128 файлов присутствуют в `[ProjectData]`;
- на A1 действительно `sample_001`;
- первые 16 pad играют;
- несколько дополнительных pads (например, 18–25) содержат семплы и не ломают загрузку.

## Если что-то не работает

Зафиксируйте:

- имя проекта;
- номер pad/ноты;
- что именно произошло: тишина, обрезка, не тот семпл, ошибка загрузки;
- прошивку MPC Sample.

После этого правки вносятся в `xpj_schema.py` и `sample_map.py`.
